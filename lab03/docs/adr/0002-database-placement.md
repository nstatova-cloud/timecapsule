# ADR-0002. Размещение базы данных

- Статус: принято
- Дата: 2026-10-28

## Контекст

В ЛР2 приложение и PostgreSQL находились на одном сервере. В ЛР3 приложение и базу данных нужно разделить. База должна быть доступна приложению, но не должна быть доступна напрямую из интернета.

## Решение

Размещаем PostgreSQL на отдельном `db-server` в приватной подсети `private-a`.

`db-server` не имеет публичного IP-адреса. Подключение к PostgreSQL на порту 5432 разрешено только от Security Group сервера приложения.

## Рассмотренные альтернативы

- База данных на одном сервере с приложением. Проще в настройке, но приложение и база не изолированы друг от друга.
- Отдельный сервер базы данных в публичной подсети. Приложение и база разделены, но сервер базы находится в подсети с маршрутом в интернет.
- Отдельный сервер базы данных в приватной подсети. База отделена от приложения и не имеет прямого доступа из интернета. Этот вариант выбран.

## Последствия

- Плюс: `db-server` не имеет публичного IP-адреса и постоянного маршрута в интернет.
- Плюс: доступ к PostgreSQL разрешён только от `app-server`.
- Минус: для установки обновлений на `db-server` нужен временный NAT Gateway. Его создаём только на время обновления и после этого удаляем, потому что NAT Gateway оплачивается за время работы и переданный трафик.
- `app-server` использует Elastic IP, чтобы его публичный адрес не менялся после остановки и запуска. Elastic IP оплачивается даже при остановленном сервере.
- Когда перед приложением появится балансировщик нагрузки, пользователи будут обращаться к балансировщику, поэтому постоянный Elastic IP для `app-server` больше не будет нужен.
